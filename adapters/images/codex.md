# Codex image adapter (automated, no API key)

Read by: `${CLAUDE_PLUGIN_ROOT}/skills/generate-images/SKILL.md`, for any `images.md` slot with `Type: ai-prompt` (the type name is historical — see `${CLAUDE_PLUGIN_ROOT}/adapters/images/ai-prompt.md`). This is the dispatch procedure; the prompt-quality bar the slot's `Prompt:` block already satisfies lives in `ai-prompt.md`.

## What this adapter produces

A real image file at `{assets_dir}/<slug>/<Suggested filename>`, generated by codex's built-in gpt-image model via the `${CLAUDE_PLUGIN_ROOT}/skills/generate-image-codex/SKILL.md` skill. No API key and no provider config are needed — codex authenticates through its own codex/ChatGPT login. Requires the `codex` CLI on PATH with a working login (a runtime prerequisite, checked softly by the blog-setup wizard; a missing codex degrades per §Failure handling, it never breaks the pipeline).

## Dispatch

For each `Type: ai-prompt` slot, invoke `${CLAUDE_PLUGIN_ROOT}/skills/generate-image-codex/SKILL.md` with the slot's `slug`, its `Prompt:` block verbatim, its `Suggested filename`, and its `Aspect ratio`. One slot per codex run (the skill's own gotcha); loop over slots sequentially.

## Disposition

- **Success** (the file exists, non-empty, passes the skill's view-and-verify step) → record the slot under `rendered` in the `generate-images` manifest.
- **Failure** (codex not on PATH, not logged in, generation error, or the output fails verification twice) → record the slot under `failed` with a reason string. The slot's `Prompt:` block in `images.md` is left untouched and remains exactly the pasteable prompt a human can run through any AI image tool by hand — a non-blocking manual fallback. A failed slot never aborts the run; continue with the remaining slots.

## Idempotency (resume)

`generate-images` skips an `ai-prompt` slot whose `Suggested filename` already exists (non-empty) at `{assets_dir}/<slug>/`, before this adapter is invoked for that slot. A resume run therefore generates only the missing subset.
